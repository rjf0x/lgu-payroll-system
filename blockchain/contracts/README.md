# Payroll Integrity Registry (BESU-02)

Separate Solidity workspace; no Laravel RPC binding or payroll workflow changes.
Requires Node >=22.13, npm and the BESU-01 network running. All contract tests use
**real Besu**, not an in-memory substitute. They deploy disposable registry
instances and submit fictional random references/hashes on the development chain.

From this directory:

```powershell
npm ci --ignore-scripts
npm run compile
npm run init:signers
npm test
npm run deploy
npm run verify
```

Initialize signers once. On later runs omit `init:signers`; it deliberately refuses
to overwrite `private/`, even following partial initialization. Never remove that
directory to troubleshoot an existing registry: its administrator cannot be
changed. No secret is printed. Windows ACLs are restricted before key creation;
POSIX directory/file modes are 0700/0600. Back up credentials securely if retaining
this chain. Keystores and their random password files share an operator-only
directory for unattended **development** use; this is not production key custody.
The outsider signer exists only for negative tests. Node-validator keys are never
used as contract accounts. Do not run scripts concurrently with the same signers.

`BESU_RPC_URL` defaults to `http://127.0.0.1:18545`; only local HTTP endpoints are
accepted. Tooling checks chain ID 20261030 and the real Besu client. Transactions
are signed locally, use explicit legacy gas price zero and wait for successful,
canonical receipts. The network's disabled balance check allows fresh accounts
without allocating funds. No RPC account unlock or frontend wallet is used.

## Contract interface

- Constructor takes separate administrator and initial authorized writer addresses.
  The administrator is fixed for the life of this minimal registry and has no
  implicit write permission. Custody loss requires a new registry and migration
  policy; production governance/rotation is not implemented.
- `setWriter(address,bool)` is administrator-only and grants/revokes writers.
  Emits `WriterAuthorizationChanged` on changes. Zero addresses are rejected.
- `record(bytes32 batchVersionRef,bytes32 commitmentHash)` is writer-only.
  New nonzero references/digests emit `CommitmentRecorded`. An authorized retry
  with the identical digest returns false, emits no new event, and preserves the
  original writer/time. A different digest for an existing reference reverts.
- `lookup(bytes32)` is public read-only and returns SHA-256 bytes, original writer,
  timestamp and explicit existence flag. Missing references return `exists=false`.

References are opaque 32-byte values; never encode employee IDs, names, salary
amounts or reversible payroll identifiers. The tests use random references. A
future application mapping can use a domain-separated SHA-256 of an opaque
finalization UUID (including a namespace/schema version); choosing and persisting
that mapping belongs to later integration phases. The contract treats the digest
as bytes32 and does not recalculate a payroll hash or prove payroll correctness.
SHA-256 commitments are distinct from Ethereum Keccak transaction/code hashes.
Corrections require new references; there is no update/delete commitment method.

## Build and deployment records

Solidity 0.8.38 is pinned, optimized for 200 runs, with explicit Shanghai output
matching the existing genesis. `npm run compile` writes the required public ABI
to `abi/PayrollIntegrityRegistry.json`; full generated bytecode stays ignored in
`artifacts/`. The lockfile pins dependencies. A `tmp` 0.2.7 override fixes the
compiler package's vulnerable transitive 0.2.6 dependency.

`deployments/local.json` records only public chain identity, contract address,
administrator/writer addresses, deployment transaction, canonical block, compiler,
runtime code hash and ABI location. It is specific to the current development
chain; rebuilding BESU-01 with new keys creates a different genesis and requires
an explicitly managed new deployment record.

The deploy script journals the signed transaction's hash, expected address and
nonce **before** broadcast, without storing signed bytes or credentials. An
uncertain outcome remains in ignored `deployments/local.pending.json`; another
run reconciles a known receipt or stops without sending another transaction.
Do not delete pending state and retry blindly. Successful reruns verify and reuse
`local.json` without broadcasting. Verification checks genesis/chain, successful
canonical receipt, creation input against current compiler/source/constructor,
runtime hash, administrator and initial writer authorization. Revoking that writer
intentionally makes this initial-authorization verification fail until the
deployment verification policy is explicitly updated.

Tests leave their synthetic contract instances and transactions on the local
chain. No confidential payroll data is submitted. No actual application snapshot
is anchored. Existing BESU-01 ACL/root-container limitations remain; this phase
does not repair or relabel those findings.
